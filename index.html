vir6il

say “Virgil”

Apps kept apart from each other and from the machine, working together only through conversations they are allowed, and a desktop made of such apps. On Fedora, and able to seal it.

  • Every app can be spoken to

    What an app offers, you can type in the terminal: calculator/tape evaluate "2 + 3". Other apps ask in the same way.

  • AI works in your apps, as you do

    An agent speaks to your apps the way you do, and only where you let it. In Pixels, for example, it paints in the same picture beside you, its strokes appearing as it makes them. The models can run on your own machine.

  • No files, no folders

    Everything stays in the app that keeps it, with as many labels as you like. The Library shows it all, and Pick and Share move things between apps without a file dialog.

  • Every permission on record

    An app reaches only what it was allowed. You can see every permission you gave, and take it back.

The technology

  • Rust and WebAssembly at the core. The runtime is written in Rust and runs Wasm apps in its own build of Wasmtime. Apps are written in TypeScript, which runs as written with no build step, in Python, or in Rust compiled to Wasm.
  • Shared memory instead of messages. Two apps in a conversation read the same bytes in place. Each protocol is described once in WIT, with views generated for Rust, TypeScript and Python. A round trip between two apps takes about a tenth of a millisecond.
  • Answers that stream. A long answer comes in chunks, each one asked for by the reader, and a window's page receives them as server-sent events. Nothing is paged or polled.
  • A desktop of its own. Its own Wayland compositor, built on smithay, and its own build of WPE WebKit. Every window is a web page painted by the GPU, which also decodes video where the driver can.
  • With a screen or without. The same runtime runs a desktop or a server with no screen, which its terminal reaches over ssh.

Privacy and security

  • Confined below the app. A Wasm app reaches only the memory of the conversations it was given. A TypeScript app runs in a WebKit process of its own, and a Python app in a process with no files and no network. Native code is Rust only, and comes only from vir6il's own catalog.
  • Permissions that lapse, decisions on record. An app asks while you use it. On a desktop, a permission unused for 90 days is taken back. Every decision goes into an append-only trail, chained by hashes.
  • A sealed Fedora. sudo vir6il seal makes every login, at the console, in GDM or over ssh, reach vir6il and nothing else. Other accounts and root are locked, and a root action needs a fresh confirmation: a touch of a security key, or the administrator's password. vir6il unseal puts everything back.
  • Private by default. Each app keeps its own cookies and website data. Activity shows each app's network traffic, and local models run in a process refused the network.
  • Passkeys, a sign-in server, inspection from afar. Signing in with a security key or a passkey held in the TPM. Identity, vir6il's own OpenID Provider, for an organisation's machines. Inspecting any app from another machine's browser.

Your own apps

  • An app is a folder. It holds a manifest, app.json5, a backend in TypeScript, Python or Rust, and the web pages of its windows.
  • Spoken to from the start. Every resource an app names in its manifest can be reached from the terminal, from other apps and from agents, under the same permissions.
  • Storage comes with it. Key-value storage with JSONPath queries, SQLite and blob storage are services the app asks. It keeps no files of its own.
  • Your catalog beside ours. Packages are GitHub releases, every file named and checked by its hash. An organisation publishes its own and adds it as a source in Applications.
  • Apps in any browser, and a builder. An app's windows served to any browser, not only to vir6il's desktop. And an app in vir6il for making apps, with an agent beside you.

Deciding on it

  • Yours to run. It installs on Fedora 43 from public releases. No account with us, and no cloud console.
  • Least privilege, with the evidence. Code from others reaches only what it was granted, and the system itself records who could reach what, since when, and why.
  • What each app costs. Activity shows each app's memory, processor, disk and network use.
  • AI under your rules. Agents act through the same permissions as people, a person approves the changes they make, and the models can run on the machine itself.
  • One utility to begin with. The first release is vir6il for Fedora 43 on x86_64. It opens vir6il's terminal or desktop, and seals a server or a desktop.

Every app in a room of its own. Every door is yours to open.
